# Singular — spec (v0.2, 2026-09-24; amended 2026-09-25, 2026-10-07/08 and 2026-10-13)

Claude Code plugin (plugin id `singular@singular`, npm package `singular-skill`, one user-facing command `/singular <subcommand>`) that, on every prompt, (1) routes to already-installed skills, (2) detects the project stack and injects it, (3) on a local miss, discovers third-party skills on skills.sh, gates them (owner allowlist, install floor, audit), and (4) loads them **ephemerally** (text only, never written to `~/.claude/skills`) when the user types `/singular load`, or automatically when `mode: "auto"` is explicitly enabled. Persistent installs go through `/singular add`, which pins to a commit SHA and rejects skill folders that would become plugins. Installation is two commands (`npm install -g singular-skill && singular install`): the `singular` CLI copies the plugin payload to `~/.claude/singular/plugin/` and registers it with `claude plugin marketplace add` + `claude plugin install singular@singular` (see "bin/singular-cli.js").

Grounding: `research/2026-09-15-auto-skill-discovery-feasibility.md`. Key measured facts it relies on:
- `UserPromptSubmit` command hooks run once before every prompt (never per tool call), get JSON on stdin (`session_id, transcript_path, cwd, prompt_id, permission_mode, hook_event_name, prompt`; for a typed slash command `prompt` is the raw slash text; piped stdin is appended to the prompt), may return `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"..."}}` (10,000-char cap; overflow spilled to file). Hooks cannot rewrite the prompt.
- `UserPromptExpansion` hooks fire when a typed `/command` expands; matcher = the plugin-prefixed command name (`singular:singular`, hence the `(^|:)singular$` regex); stdin has `command_args`; may return `additionalContext` or block with exit 2. Verified live on Claude Code 2.1.282 (2026-09-24) and 2.1.293 (2026-10-07).
- `SubagentStart` hooks fire when the Agent tool spawns a subagent; stdin `{session_id, prompt_id, transcript_path, cwd, agent_id, agent_type, hook_event_name}`; `hookSpecificOutput.additionalContext` reaches the subagent (context-only event; exit 2 does not block). Verified live on 2.1.293: the subagent echoed the injected `[singular] Stack:` line. A subagent's own prompt never fires `UserPromptSubmit`, and the parent's context is not inherited; the parent is resumed with a synthetic `<task-notification>` prompt that does fire `UserPromptSubmit`.
- A skill installed by a hook is NOT in the model's skill list for the first request of that turn. So never rely on hot-reload inside the turn; inject text instead.
- `GET https://skills.sh/api/search?q=<q>&limit=<n>` is anonymous JSON `{skills:[{id, skillId, name, installs, source}]}`; ranking is lexical, not install-weighted → always re-sort by `installs`, use `limit` ≥ 200.
- `GET https://skills.sh/api/v1/skills/audit/{source}/{skill}` public; advisory.
- `npx -y skills@1.5.26 use owner/repo#<40-hex-sha>@skill` prints SKILL.md wrapped in a prompt, writes only to a temp dir. `#sha` pinning is undocumented but works (`parseFragmentRef`, `cloneAtSha`). Pin the CLI version too.
- `npx skills add` copies the WHOLE folder; a folder with `.claude-plugin/`, `hooks/`, `.mcp.json`, `bin/` etc. becomes a `<name>@skills-dir` plugin at user scope on next session with no trust dialog. → `/singular add` must inspect and refuse.
- Anthropic: use skills only from trusted sources. Base rate ~13% critical (Snyk). Scanners bypassable. Hence defaults: `mode: "suggest"`, allowlist required, install floor 1000.

## Zero dependencies. Node ≥ 20 (uses `fetch`, `node:test`). ESM (`"type":"module"`). No npm packages.

                                  `singular install` registers ~/.claude/singular/plugin (the payload copy), a checkout can be registered the same way by hand

State directory `~/.claude/singular/` (or `$SINGULAR_HOME`): `config.json`, `cache/`, `loaded.json`, `installed.json`, `singular.log`, `spill-*.md`, `.auto-mode-warned`, and `plugin/` (the payload copy the CLI registers; `plugin.prev/` is the previous copy kept for rollback). Environment variables: `SINGULAR_HOME`, `SINGULAR_MODE`, `SINGULAR_DEBUG`, the test seams `SINGULAR_REGISTRY_BASE`, `SINGULAR_GIT_BASE`, `SINGULAR_SKILLS_DIR`, `SINGULAR_TEST_ALLOW_AUTO`, and the e2e runner's `SINGULAR_E2E_*`. Context and log lines are tagged `[singular]`; loaded text is delimited by `<singular-loaded ref="...">`.

## Config — `~/.claude/singular/config.json` (created on first run from defaults; env `SINGULAR_HOME` overrides dir)
```json
{
  "mode": "suggest",                       // "off" | "local" | "suggest" | "auto"
  "allowlist": ["anthropics", "vercel-labs", "microsoft", "multica-ai"],
  "installFloor": 1000,
  "maxLocalSkills": 3,
  "maxCandidates": 2,
  "minPromptChars": 40,
  "remoteTimeoutMs": 2500,
  "totalBudgetMs": 6000,
  "contextBudgetChars": 2000,
  "cacheTtlHours": 24,
  "skillsCliVersion": "1.5.26",
  "requireAuditPass": true,
  "stackDetection": true,
  "blockedRefs": [],
  "pinnedSkills": [],                      // added 2026-09-25: installed names or allowlisted refs injected once per session
  "prefetch": true                         // added 2026-09-25: background prefetch of the top suggestion's text
}
```
`mode`: off = hook no-ops; local = only installed-skill routing + stack; suggest = local + remote candidates as text suggestions; auto = local + fetch the single best gated candidate and inject its (sanitized) text without confirmation. `auto` must show a one-time warning on first use (as the hook's `systemMessage`; stderr of an exit-0 hook is not shown to the user) and README must document the risk and the cost. `auto` is honoured only from the default `~/.claude/singular/config.json`; the environment can only lower the mode (see Amendments).

## Module APIs (fixed; builders must match exactly)

### lib/log.js
`export function log(level, msg, extra?)` → writes JSON lines to `$SINGULAR_HOME/singular.log` (default `~/.claude/singular/singular.log`), never stdout. `export function timer()` → `{ elapsed(): ms }`.

### lib/config.js
`export function loadConfig(env = process.env) → Config` (defaults merged with file; validates types; unknown keys kept). `export const DEFAULTS`. `export function configPath(env)`, `export function homeDir(env)` (mkdir -p). `export function isAllowlisted(source, allowlist)` — `source` is `owner/repo`; allowlist entries are `owner` or `owner/repo` (exact, case-insensitive).

### lib/cache.js
`export function cacheGet(key, ttlHours) → any|null`, `export function cacheSet(key, value)`; files under `$SINGULAR_HOME/cache/<sha256(key)>.json` with `{ts, value}`.

### lib/skill-index.js
`export async function buildIndex({cwd, home}) → Skill[]` where `Skill = {name, description, path, scope: "user"|"project"|"plugin"|"synced", pluginName?}`. Scans: `$HOME/.claude/skills/**/SKILL.md` (depth ≤ 3; `synced/` → scope synced), `<cwd>/.claude/skills/**/SKILL.md`, and installed plugins' skills (read `$HOME/.claude/plugins/installed_plugins.json` if present to get install paths; else scan `$HOME/.claude/plugins/marketplaces/*/**/skills/*/SKILL.md` and `$HOME/.claude/plugins/cache/**/skills/*/SKILL.md`, depth-limited). Dedupe by name (project > user > plugin). Parse YAML frontmatter minimally (name, description; `description` may be multi-line `>`/`|`). Cache the index for 60 s keyed by dir mtimes. Must finish < 150 ms on ~100 skills.

### lib/score.js
`export function tokenize(text) → string[]` (lowercase, split non-alnum, drop stopwords, keep tokens ≥ 2 chars, simple stemming: strip trailing s/ing/ed). `export function scoreSkills(prompt, skills, {max=3, minScore=1.5}) → {skill, score, matched: string[]}[]` — BM25-lite over name+description with name tokens weighted ×3; exact multi-word phrase matches ×2; return sorted, thresholded. `export function extractKeywords(prompt, {max=4}) → string[]` — top TF tokens minus stopwords, prefer tech nouns (a small built-in lexicon: react, nextjs, tailwind, svelte, vue, django, fastapi, postgres, supabase, stripe, playwright, docker, k8s, terraform, rust, go, swift, kotlin, ...).

### lib/stack.js
`export async function detectStack(cwd) → {summary: string, tags: string[]}` — reads package.json (deps → framework tags: next, react, vue, nuxt, svelte, astro, remix, express, hono, nest, tailwind, prisma, drizzle, supabase, trpc, vitest, jest, playwright, typescript), lockfile → pm, `tsconfig.json` strict, `pyproject.toml`/`requirements.txt` (django, fastapi, flask, pytest), `go.mod`, `Cargo.toml`, `Gemfile`, `pom.xml`, git branch (via `.git/HEAD` read, no subprocess). Summary ≤ 160 chars e.g. `Next.js 16, React 19, Tailwind 4, TypeScript strict, pnpm; branch main`. Never throws; unknown → `{summary:"", tags:[]}`. Cache per cwd 60 s.

### lib/refs.js
`export function parseRef(str) → {owner, repo, sha|null, skill} | null` accepting `owner/repo@skill` and `owner/repo#<40-hex>@skill`. `export function formatRef(ref)`, `unpinnedRef(ref)`, `normalizeRefCase(ref)` (lowercases owner/repo only: GitHub resolves them case-insensitively, so two spellings share one pin and one text-cache entry; the skill segment is case-sensitive). `export const REF_RE` (strict: `^[A-Za-z0-9][A-Za-z0-9-]*/[A-Za-z0-9][A-Za-z0-9._-]*(#[0-9a-f]{40})?@[A-Za-z0-9][A-Za-z0-9._-]*$` — every segment starts alphanumeric so `-y`, `--skill`, `.`, `..` can never become a flag or a path segment; `isSafeSegment` also caps a segment at 100 chars). `export async function resolveHeadSha(owner, repo, {timeoutMs}, deps) → sha` via `git ls-remote <base>/<o>/<r> HEAD` (execFile with an args array, timeout, `GIT_TERMINAL_PROMPT=0`; base is `https://github.com` or the `SINGULAR_GIT_BASE` test seam). A credential prompt (what GitHub does for a missing or private repository) is reported as `repository not found or private (GitHub asked for credentials): <raw detail>`. `export function isSha(s)`.

### lib/git.js
`GITHUB_BASE`, `gitBase(env)`, `repoUrl(owner, repo, env)`; `describeGitFailure(what, r, timeoutMs)` (the credential-prompt mapping above); `runExecFile(impl, file, args, opts)` (promise wrapper, never rejects, closes stdin); `cloneAtSha({owner, repo, sha, dest, timeoutMs, execFileImpl, env, tmpdir}) → {ok} | {ok: false, step, message}` = `git init -q` / `remote add origin <url>` / `fetch --depth 1 origin <sha>` / `-c core.symlinks=true checkout -q FETCH_HEAD` in `dest`; `findSkillDirs(root) → {dir, rel, name}[]` (every SKILL.md folder, frontmatter name included, `.git`/`node_modules` skipped). Shared by `lib/refs.js`, `lib/registry.js` (git-based text fetch under the seam) and `bin/singular.js add`.

### lib/registry.js
`export async function searchSkills(query, {limit=200, timeoutMs}) → Candidate[]` hitting `https://skills.sh/api/search?q=&limit=`; `Candidate = {source: "owner/repo", skill, installs, url}`; sorted by installs desc; AbortController timeout; on any error → `[]` (never throws). `export async function auditSkill(source, skill, {timeoutMs}) → {status: "pass"|"warn"|"fail"|"unknown", raw}` from `/api/v1/skills/audit/{source}/{skill}`. `export function gateCandidates(cands, config, extra={}) → {accepted: Candidate[], rejected: {cand, reason}[]}` applying allowlist, installFloor, blockedRefs, dedupe forks (same skill name from non-allowlisted source dropped). `export async function fetchSkillText(ref, {cliVersion, timeoutMs}) → {text, sha}` running `npx -y skills@<cliVersion> use owner/repo#sha@skill` with `DISABLE_TELEMETRY=1`, cwd = a fresh temp dir, execFile (no shell). If ref.sha is null → resolveHeadSha first. Strip the CLI's wrapper prose, return SKILL.md text. `export function sanitizeSkillText(text) → {text, stripped: string[]}` — remove frontmatter keys `allowed-tools, disallowed-tools, hooks, context, agent, shell, paths, model`; drop lines containing `` !` `` or fenced ```` ```! ```` blocks; drop `@`-file references (`@path` tokens at line start); cap 9,000 chars; record what was stripped. Discovery pipeline: `export async function discover(prompt, {config, stackTags, timeoutMs}) → {candidates: Gated[], keywords, cached: boolean}` = keywords → cache lookup → search (each keyword + joined query, merged) → gate → optional audit for top N → return top `maxCandidates`.

### lib/context.js
`export function composeContext({stack, localMatches, candidates, mode, budgetChars, loaded?, pinned?, notes?}) → string` — factual, ≤ budget, no imperative "you must use". Format (sections omitted when empty; the first line carries the `[singular]` tag; candidates are joined with `; `):
```
[singular] Stack: <summary>
Pinned installed skills (user-configured, consider invoking): <name>, ...
Installed skills likely relevant: <name> (matches <tok>, <tok>), <name> ...
If one of the third-party candidates below fits the request, end your reply with exactly one line `Load with /singular load <ref>` naming the single best fit; omit that line if none fits.
Third-party candidates (not loaded): <owner/repo[#sha7]@skill> (<installs> installs, audit <status>) — load with /singular load owner/repo@skill; <next candidate>
<notes, e.g. the singular command list>
Loaded third-party skill <owner/repo#sha@skill> (<reason>; text only, nothing installed). Stripped: <list>.
<singular-loaded ref="<pinned ref>">
<sanitized body, fitted under 9,500 chars with a trailing "[singular: truncated]" marker when cut>
</singular-loaded>
```
The relay line (`RELAY_LINE`) precedes the candidate list; `#sha7` is shown only when the HEAD is already cached. Budget: candidates are dropped first, then installed matches, then a hard cut; `notes` are never dropped. Exports: `TAG`, `SPILL_THRESHOLD` (9500), `HOOK_HARD_CAP` (10000), `TRUNCATION_MARKER`, `RELAY_LINE`, `fitLoadedText(text, reservedChars) → {text, truncated}`. `export function spillIfNeeded(text, home) → text|pathNote` (if > 9,500 chars write to `$SINGULAR_HOME/spill-<ts>.md` and return a short note with the path; last resort, only for oversized routing text).
`export function hookOutput(eventName, additionalContext, {systemMessage?}) → string` (JSON for stdout: `{"hookSpecificOutput":{"hookEventName","additionalContext"}}` plus a top-level `systemMessage` when given; nothing else is ever printed).

### lib/inspect.js
`export async function inspectSkillFolder(dir) → {ok: boolean, problems: string[]}` — problems if the folder contains any of: `.claude-plugin/`, `plugin.json`, `hooks/`, `.mcp.json`, `.lsp.json`, `bin/`, `monitors/`, `agents/`, `commands/`, `settings.json`, `scripts/`, symlinks, files with exec bit; or SKILL.md frontmatter has `hooks`, `allowed-tools`, `disallowed-tools`, `context`, `agent`, `shell`, `paths`, `user-invocable: false`; or body has `` !` `` / ```` ```! ```` / line-leading `@` refs. Never modifies.

### bin/on-prompt.js
Read stdin JSON. Exit 0 with no output when (the logged `skipped` strings, in evaluation order): `mode off`; `empty prompt` (whitespace only after the `<pasted_content>` wrapper lines are stripped); `slash command` (the RAW prompt, trimmed, starts with `/` — Claude Code's own rule, so a pasted block whose first inner line is a slash command is an ordinary prompt); `task notification (synthetic prompt)` (`<task-notification>`, delivered to the main agent after a backgrounded subagent finishes); `system reminder (synthetic prompt)` (a bare `<system-reminder>…</system-reminder>` block); `own output` (starts with `[singular]`; a mid-prompt mention is routed); `prompt shorter than minPromptChars (N < 40)` (inclusive boundary: 40 characters route, 39 do not). Corrupt stdin or another `hook_event_name` also produce no output. `--dry-run` prints `[singular] (no context: <reason>)` for a skipped prompt. Exception: a prompt that mentions the plugin (`/singular`, or `/singular-find`, or the word `singular` next to `skill(s)`/`plugin(s)`/`command(s)`/`mode(s)`/`status`/`config`/`hook(s)`; the word alone is ordinary English and must not trigger it) always gets the one-line command list (`COMMANDS_HINT`: the `/singular` subcommands), even under minPromptChars, because every subcommand except `find` is hidden from the model. Else within `totalBudgetMs` (hard deadline; remote step skipped if < 1500 ms left): index+score local, stack detect, and if mode ∈ {suggest, auto} and no *strong* local match (`isStrongMatch`, see Amendments) → discover. In `auto`: fetch top candidate text (pinned; if no sha, resolve) → sanitize → append as `Loaded third-party skill <ref> (auto mode, user-configured):` + text within 9,000 chars. Print `hookOutput("UserPromptSubmit", ctx, {systemMessage})` only if ctx or systemMessage non-empty. `systemMessage` carries the one-time auto warning and, in suggest (or auto without a load), `[singular] N third-party skill(s) may fit this prompt (not loaded): /singular load a/b@c, ...` — each ref announced once per `session_id` (cache `session:<id>:suggested`), so the user learns about a candidate without the model relaying it. Any exception → log, exit 0 silently. The info log line carries `sessionId`, `promptId`, `hint`, timings. Also `--dry-run "<prompt>"` CLI arg for testing prints the context to stdout (never consumes the one-time auto warning marker; `autoSkipped` says the prefetch did not run).

### bin/on-expand.js
Hook mode: `hooks.json` matches `(^|:)singular$`, so the hook fires for every `/singular ...` expansion (`command_name` `singular:singular`). It acts only when `command_args` starts with the subcommand `load` (`load <ref> [--update]`); for every other subcommand (`status`, `help`, `find`, `add`, `mode`, nothing) it exits 0 with **no output**, so the `skills/singular/SKILL.md` body runs the dispatcher through Bash. Read stdin JSON (`command_name`, `command_args` per spike). Validate args (the text after `load`): exactly one ref matching `REF_RE`; exactly one ref matching `REF_RE`; owner allowlisted (else print reason to stderr, exit 2 = block). Owner/repo are lowercased (`normalizeRefCase`) before pinning and caching. Resolve sha if missing; record `{ref, sha, ts}` in `$SINGULAR_HOME/loaded.json` (first load pins; later loads reuse unless `--update` present in args). fetchSkillText → sanitize → output `hookOutput("UserPromptExpansion", ctx)` where `ctx` is `[singular] The user explicitly loaded third-party skill <pinned ref> via /singular load (pinned <resolved | loaded.json | resolved (--update) | arg>; text only, nothing installed). Contents (sanitized; stripped: <list | nothing>):` followed by `<singular-loaded ref="<pinned ref>">`, the body (fitted under 9,500 chars, `truncated N chars to fit the 9,500-char hook budget` appended to the stripped list when cut) and `</singular-loaded>`. A block is `[singular] <reason>. usage: /singular load owner/repo@skill  or  /singular load owner/repo#<40-hex-sha>@skill  [--update]` on stderr with exit 2 (hook mode) or exit 1 (CLI mode); reasons: `unknown option <flag>`, `missing skill reference`, `expected exactly one skill reference, got N`, `invalid skill reference "<first 80 chars>"`, `refused: owner "<o>" is not in the allowlist [...]. Add "<o>" (or "<o/r>") to "allowlist" in <config> if you trust that source, then retry.`, `refused: <o/r@s> matches "blockedRefs" in your config.`, `could not resolve HEAD of <url>: ...`, `could not fetch <ref>: ...`, `<ref> has no usable text after sanitizing`. `loaded.json` entry per unpinned (case-folded) ref: `{ref, sha, ts, lastTs, loads, chars, stripped}`. Also support direct CLI use: `node bin/on-expand.js <ref> [--update] [--json]` prints `[singular] loaded <pinned ref> (pinned <source>; stripped: <list | nothing>)`, a blank line and the sanitized text (`--json`: `{ref, sha, pinSource, stripped, text}`); `--prefetch` (spawned detached by on-prompt) caches HEAD and text without pinning, prints nothing and exits 0 even when blocked. Measured 2026-10-08: first load 3.2 s wall (HEAD resolve + pinned `npx skills use`, warm npm cache), cached text 0.05 s, `--update` 0.35 s.

### bin/on-subagent.js (SubagentStart)
Read stdin JSON `{session_id, transcript_path, cwd, prompt_id, agent_id, agent_type, hook_event_name: "SubagentStart"}` (2.1.293; `permission_mode` absent). Ignore any other event or input without `cwd`. hardenEnv + loadConfig; nothing when mode is off or `stackDetection` is false; otherwise ONLY `detectStack(cwd)` and print `{"hookSpecificOutput":{"hookEventName":"SubagentStart","additionalContext":"[singular] Stack: <summary>"}}`. No index, no scoring, no network, no prefetch, no pinned or loaded third-party text (never forwarded to subagents). Measured 35 ms wall. SubagentStart is "context only": exit 2 does not block. `--dry-run [--cwd]` prints the line.

### bin/singular.js add `<ref>` [--yes] [--json]
Requires allowlisted owner; refuses if `~/.claude/skills/<skill>` already exists BEFORE any network round trip; then resolves sha (pin). Does **not** use the skills CLI: `lib/git.js cloneAtSha` fetches the pinned commit into a temp dir (`git init` / `remote add origin https://github.com/<o>/<r>` / `fetch --depth 1 origin <sha>` / `checkout FETCH_HEAD`, execFile, no shell), locates the skill by an exact, case-sensitive directory or frontmatter name, rejects any `120000` / `100755` / `160000` entry from `git ls-tree -r`, runs `inspectSkillFolder` on the checkout, and only then copies (`cpSync`, `dereference: false`, `errorOnExist`) with a before/after snapshot of `~/.claude/skills` (exactly one new entry = the target) and a post-copy re-inspection; any failure removes exactly the folder this run created (guarded three ways) and prints `REJECTED: <problems>`; else prints `INSTALLED <ref> sha <sha>` + audit JSON + `Run /reload-skills or start a new session`. A rejected skill never touches `~/.claude/skills`.

### bin/singular.js find `<query>` [--limit N] [--all] [--json] [--cwd <dir>] → prints installed matches, the gated candidates table (`ref  installs  audit  allowlisted?`), the rejected count grouped by reason (`already installed locally (...)` collapsed to one line), `Best allowlist-only rejection: <ref> (<installs> installs, matched <tokens>) - add "<owner>" to "allowlist" in <config path>` when the most relevant rejected entry was refused only for its owner, and the top rejected entries **by relevance** (same BM25-lite + log10(installs) as the accepted ones; `--all` for every entry). During a skills.sh cooldown with cached catalogs it prints the real count `(from cached catalogs only)`; `Rejected: n/a` only when nothing could be evaluated. `--json` option (rejected entries carry `rank`, `matches`, `matched`; plus `bestRejected`, `configPath`). Known issue (observed 2026-10-08): `main()` calls `process.exit()` right after one large `process.stdout.write()`, so when stdout is a pipe the output is cut at 65,536 bytes (`--json` for a 500-entry rejected list is ~116 KB; the same run redirected to a file is complete). The plain report (~60 KB with `--all`) stayed under the limit.

### bin/singular.js mode `[off|local|suggest|auto]` [--json] → shows the effective mode and its source (including hardenEnv notes such as an ignored relative `SINGULAR_HOME`, printed as `! ...` lines, also under `warnings` in `--json`), or rewrites only the `mode` key; refuses `auto` in a redirected home; refuses to touch an unreadable (EISDIR) or corrupt file. Every message starts with `[singular]`.

### bin/singular.js `<status|help|find|add|mode> [...]` (dispatcher)
One entrypoint for everything the `/singular` skill body runs through Bash and for the terminal proxies of the CLI; the implementations live in `lib/commands/{status,find,add,mode}.js` and are re-exported by `bin/singular.js`. A leading option without a subcommand (`--json`, `--cwd`) means `status`; `load <ref> [--update] [--json]` is a terminal convenience that calls the CLI mode of `bin/on-expand.js` (it never falls through to the hook mode, which would wait for stdin JSON). `status [--json] [--cwd <dir>]` prints the report that `collectStatus`/`formatStatus` produced as a stand-alone status script until 0.2.0 (first line `[singular] singular <version>  plugin root: <root>`, then state dir, config path, every config key, `! ...` warnings, env overrides, active test seams, effective-vs-file mode, the auto warning, pinned skills, `installed skills indexed: N (...)`, `stack (<cwd>): ...`, cache stats, cooldown, `loaded pins (/singular load, ephemeral): N`, `persistent installs (/singular add): N`, `log: <path>` + last 5 lines; `--json` the same facts as an object) followed, with no argument, by the one-screen help. `help` prints the subcommand list. `find`, `add`, `mode` are the sections below. Exit codes and output formats are those of the former 0.1.x per-command scripts (0 on success; `find` without a query, `mode` with a bad value, `add` with a rejection all exit 1); an unknown subcommand prints `[singular] unknown subcommand "<x>"; expected one of status | help | find | load | add | mode` plus the help to stderr and exits 1. The 0.1.x per-command scripts in `bin/` no longer exist (no shims).

### bin/singular-cli.js (the `singular` binary; `"bin": {"singular": "bin/singular-cli.js"}`)
Zero dependencies; every subprocess is `execFile` with an argument array; `CLAUDE_CONFIG_DIR` and the rest of the environment are passed through to `claude`, so tests isolate with a fresh `CLAUDE_CONFIG_DIR`. Exit 1 with a clear message on any failure; never a partially registered state (if a `claude plugin ...` step fails the message names that exact command and how to retry). `--help` prints the list.
- `install [--dir <path>] [--dry-run] [--json]`: (1) `node >= 20` and `claude` on `PATH` with version `>= 2.1.282` (parsed from `claude --version`); (2) copy the payload (`.claude-plugin`, `hooks`, `skills`, `bin`, `lib`, `package.json`, `LICENSE`, `README.md`, `config.example.json`) from the package's own directory (resolved from `import.meta.url`) to `~/.claude/singular/plugin/` (or `--dir`), atomically: write `plugin.tmp`, keep the previous copy as `plugin.prev`, rename; the registered path therefore survives `nvm`/Node upgrades and `npm update`; (3) `claude plugin marketplace add ~/.claude/singular/plugin`, or `claude plugin marketplace update singular` if the marketplace exists; (4) `claude plugin install singular@singular`, or `claude plugin update singular@singular` if already installed; (5) print `Installed. Open a new Claude Code session (or run /reload-plugins) and type /singular`. `--dry-run` prints the plan only; `--json` the steps as JSON.
- `update`: same as `install` (re-copy from the currently installed package, then marketplace update + plugin update).
- `uninstall [--purge]`: `claude plugin uninstall singular@singular`, `claude plugin marketplace remove singular`, remove `~/.claude/singular/plugin`; `--purge` also removes the config, cache, log and pins.
- `status`: node and claude versions, payload path + version, marketplace registered?, plugin installed/enabled? (parsed from `claude plugin list --json`), config path + mode, last 5 `singular.log` lines. `doctor` = `status` plus an actionable hint per problem.
- `find | add | mode | load <...>`: proxies to `bin/singular.js` (`load` to the direct CLI mode of `bin/on-expand.js`), same output and exit codes as inside Claude Code.

## Amendments (2026-09-25, from the review of 2026-09-24)

Exported function names and signatures above are unchanged; these are behaviour changes, each covered by a regression test in `test/`.

- **Environment is untrusted** (`lib/config.js` `hardenEnv`, `loadConfig`): a repository's committed `.claude/settings.json` `env` reaches the hook process. `SINGULAR_MODE` can only lower the mode below the file's value; `SINGULAR_HOME` is honoured only as an absolute path outside the hook cwd; `mode: "auto"` counts only in the default `~/.claude/singular/config.json`; a `HOME` inside the project is replaced by the real home. The auto warning is emitted as the hook JSON `systemMessage` (`hookOutput(event, ctx, {systemMessage})`).
- **Reference grammar** (`lib/refs.js`, `lib/registry.js`): every segment must start with `[A-Za-z0-9]` (`REF_RE` = `^[A-Za-z0-9][A-Za-z0-9-]*/[A-Za-z0-9][A-Za-z0-9._-]*(#[0-9a-f]{40})?@[A-Za-z0-9][A-Za-z0-9._-]*$`); `isSafeSegment` also rejects `.`, `..` and segments over 100 chars. Registry entries are validated with the same grammar.
- **`/singular add` does not use the skills CLI to install.** It fetches the pinned commit itself (`git init/remote add/fetch --depth 1 origin <sha>/checkout FETCH_HEAD` in a temp dir), locates the skill by an exact, case-sensitive directory or frontmatter name, rejects any `120000`/`100755`/`160000` entry from `git ls-tree -r`, runs `inspectSkillFolder` on the checkout, and only then copies (`cpSync`, `dereference: false`, `errorOnExist`) with a before/after snapshot of `~/.claude/skills` (exactly one new entry = the target) and a post-copy re-inspection. A rejected skill never touches `~/.claude/skills`.
- **Inspection and sanitizer fail closed on frontmatter spellings** Claude Code honours: quoted keys (`"allowed-tools":`), uniformly indented keys (`  hooks:`), mixed case, flow mappings (`{`/`[` lines), an indented first key, `user-invocable: false` in any spelling (`lib/inspect.js` `scanRawFrontmatter`, `lib/registry.js` `sanitizeSkillText`).
- **Discovery** (`lib/registry.js` `discover`): no free-form prompt text on the wire. Per allowlisted owner one catalog request (`q=skill&owner=<o>&limit=200`, cached `cacheTtlHours`), plus at most `MAX_KEYWORD_SEARCHES` (2) unscoped searches for single words that are in the tech lexicon (`shareableKeywords`; the API is lexical and capped at 200, so a repo whose name lacks "skill" is only reachable this way), cached per word; the joined-keyword query is sent only for `/singular find` (`search: true`). At most `MAX_CONCURRENT_REQUESTS` (2) in flight. An HTTP 429 writes a 5-minute cooldown (`COOLDOWN_KEY`) shown by `/singular status` and `/singular find`. `rankCandidates` scores the prompt (+ `expandIntent` terms) against catalog names with `scoreSkills`, requires an exact stemmed name-token match that is not a hyper-common word, treats stack tags as a weak bonus, and adds `log10(installs)` as a real term. `discover()` returns the extra fields `intent`, `shared`, `queries`, `auditSkipped`, `errors`, `cooldownUntil`, `elapsedMs`.
- **`on-prompt.js`**: `<pasted_content id="…">` wrapper lines are stripped (`normalizePrompt`) before the skip checks, scoring and keyword extraction. A local match is *strong* (suppresses discovery) only when `score >= STRONG_LOCAL_SCORE` (10) and it matched >= 2 tokens or a non-generic name token (`isStrongMatch`); matches made only of `ROUTING_STOPLIST` words are dropped (`isWeakMatch`). Suggestions use the short `/singular load owner/repo@skill` form with a `#sha7` display suffix when the HEAD is cached; no `git ls-remote` on the hot path. In `suggest` a detached `node bin/on-expand.js <ref> --prefetch` caches the top candidate's HEAD and text. In `auto` the text cache (`text:<pinned ref>`, no TTL) is checked first; an inline fetch needs >= `MIN_AUTO_FETCH_MS` (4500) left, otherwise the suggestion is emitted and the text prefetched. `config.pinnedSkills` (installed names or allowlisted refs) are injected once per `session_id`. `composeContext` appended `RELAY_LINE` after the candidates (moved before them on 2026-10-07) and budgets a loaded body under `SPILL_THRESHOLD` (9,500) with `fitLoadedText` instead of spilling the whole context; `spillIfNeeded` states the 9,500 threshold.
- **`/singular mode <off|local|suggest|auto>`** (`bin/singular.js mode`, `skills/singular/SKILL.md`) rewrites only the `mode` key and refuses `auto` in a redirected home.
- **Log privacy**: `singular.log` records the keyword count and the shared tech words; extracted keywords only with `SINGULAR_DEBUG=1`.
